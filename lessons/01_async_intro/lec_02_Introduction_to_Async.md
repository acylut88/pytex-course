## 💡 Что такое асинхронность и Event Loop?

В основе асинхронного выполнения кода в Python лежит **цикл событий** (`event loop`). 

> **Event Loop** — это центральный механизм, который управляет выполнением асинхронных задач, отслеживает готовность операций ввода-вывода (I/O) и планирует их дальнейшее выполнение.

### 🔄 Ключевые понятия:
* **Корутина (Coroutine)** — это объект, описывающий потенциальное асинхронное выполнение. Функция, объявленная с ключевым словом `async def`, при вызове не выполняется сразу, а возвращает объект корутины.
* **Задача (Task)** — это зарегистрированная в Event Loop корутина. Цикл событий берет на себя ответственность за её выполнение, приостановку и возобновление. Она создается с помощью функции `asyncio.create_task()`.
* **Управление (`await`)** — когда корутина встречает ключевое слово `await`, она временно приостанавливает свою работу и отдает управление циклу событий, позволяя ему выполнять другие задачи, пока текущая ожидает (например, ответа от сети).

## 🛠 Жизненный цикл асинхронной Python-программы

Полный жизненный цикл работы асинхронного приложения в Python состоит из 6 основных этапов:

```text
  1. Запуск синхронного кода
             │
             ▼
  2. Создание и запуск Event Loop (через asyncio.run)
             │
             ▼
  3. Регистрация корутин и задач (Tasks)
             │
             ▼
  4. Конкурентное выполнение задач в цикле событий
             │
             ▼
  5. Завершение работы главной корутины main()
             │
             ▼
  6. Очистка ресурсов и остановка Event Loop
```

### 💻 Пример 1: Простейший старт приложения

Вызов `asyncio.run()` является ключевым моментом старта асинхронного приложения. Под капотом он создает Event Loop в текущем потоке, регистрирует корутину `main` и блокирует поток до завершения её выполнения.

```python
import asyncio

async def main():
    print("Hello, async world")

# Точка входа: запускает Event Loop и передает ему корутину main
asyncio.run(main())
```

### 💻 Пример 2: Работа с задачами (Tasks)

Во время выполнения `await asyncio.sleep(2)` работа корутины `worker` приостанавливается, управление возвращается в Event Loop, и программа может параллельно обрабатывать другие операции. По истечении таймера цикл событий возобновляет `worker`.

```python
import asyncio

async def worker():
    print("Start")
    await asyncio.sleep(2)  # Передача управления циклу событий
    print("Worker done after sleeping")

async def main():
    # Регистрация корутины в Event Loop в виде Task
    task = asyncio.create_task(worker())
    print("Task created")
    
    # Ожидание выполнения задачи
    await task

asyncio.run(main())
```

## 🌐 Жизненный цикл веб-приложения (на примере FastAPI)

Запуск асинхронного веб-приложения на базе фреймворка FastAPI устроен сложнее и задействует **ASGI-сервер**.

### 🔀 Что такое ASGI?
> **ASGI** (*Asynchronous Server Gateway Interface*) — это асинхронный стандарт взаимодействия между веб-сервером и веб-приложением на Python. Он определяет, как сервер передает входящие запросы приложению и как приложение возвращает ответы в асинхронной среде.

При установке FastAPI по умолчанию ставится библиотека `uvicorn`, которая и выполняет роль ASGI-сервера.

### 🔄 Этапы жизненного цикла веб-сервера:

1. **Запуск сервера:** Команда `uvicorn main:app` запускает процесс (где `main` — это файл `main.py`, а `app` — экземпляр FastAPI).
2. **Инициализация:** Именно внутри `uvicorn` создается и запускается главный `event loop` для всего приложения FastAPI. Сервер настраивает цикл событий и передает управление серверной корутине.
3. **Подключение ресурсов:** После старта цикла событий FastAPI определяет зависимости и асинхронно подключается к внешним ресурсам (базам данных, брокерам сообщений и т.д.).
4. **Обработка запросов:** ASGI-сервер принимает сетевые соединения, обрабатывает HTTP-протокол и передает запросы в FastAPI. Все обработчики эндпоинтов (роуты) выполняются внутри **одного общего цикла событий**, конкурентно переключаясь между собой в точках `await`. При этом FastAPI отвечает только за логику и формирование ответа, не управляя сетевым вводом-выводом напрямую.
5. **Завершение работы:** Когда сервер получает сигнал остановки (или происходит критическая ошибка), `uvicorn` инициирует корректное завершение. FastAPI вызывает обработчики закрытия (`shutdown`), закрывает соединения с БД, после чего ASGI-сервер останавливает Event Loop и завершает процесс приложения.
